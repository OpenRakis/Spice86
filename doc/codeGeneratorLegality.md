# Legality catalogue - IR data-flow rewrites

Every condition a rewrite checks before it applies, what goes wrong without it, and what proves
it is load-bearing. "Trapped" means a mutation that drops the condition fails an oracle (or
fails to compile the generated code, or throws). Rows that cannot be proven by an oracle carry
one of:

- `redundant (covered by <id>)` - another condition refuses the same rewrites first;
- `unreachable` - no input in the fixtures reaches the code path;
- `readability` - an output-size or shape gate that does not change behavior;
- `not trappable` - dropping the condition is observably safe;
- `unit test only` - covered by a unit test because no fixture can produce the shape.

Observable behavior here means behavior of the emulated program. Generated code is not
required to trigger breakpoints or preserve debugger-only bookkeeping. See
[the generator's non-goals](codeGeneratorReadme.md#non-goals). Device state and subsequent
program-visible port behavior remain part of the legality checks.

A row id is a short name for one condition (a prefix for the rewrite family and a number); the
fixture section comments use the same ids. The `code` column names the IR pass member that
implements the row now. Rows whose old code was deleted and whose condition is now implied by
the IR model say so.

`dataflow_legality_traps` is the fixture added for the conditions no earlier fixture covered;
its section comments name the row ids. Mutations ran serially; each was reverted after its
run.

## Segment values (SV)

`IrSegmentValues` resolves, for the register version a statement reads, a `SegmentValue`:
`Known(constant)`, `Symbolic(root version)` or `Unknown`. Two registers hold the same value
(`SameValue`) when both are `Known` with one constant or both `Symbolic` with one root. A
`Symbolic` root is sound because an SSA version names one static definition: two registers
holding copies of root `V` at one statement hold the same dynamic value - if `V`'s definition
ran again between the two copies, the path crosses a loop header where the later-read register
is live and gets a phi, and SV-4 then needs every phi operand to have root `V`, which an operand
from outside the loop cannot. The same holds for SV-3 because `Complete` requires the definition
on every path. The shared constant-resolution helper is `IrSegmentValueResolver`, which
`IrMemoryAliasAnalysis` uses for its `SegmentValue` fields.

|----|-----------|------|------------|------------|----------|

## IrDeviceOperations (DO)

Recognizes a constant-port access sequence inside one basic block as a device protocol and
replaces it by one call on the device (`Cmos.ReadRegister` / `WriteRegister` for the 0x70/0x71
pair, `Pit.ProgramChannel` for a low/high control word plus its two channel data writes,
`Vga.SetPaletteEntry` for the DAC write index plus its three data writes,
`Vga.WriteSequencerRegister` / `Vga.WriteGraphicsControllerRegister` for the 0x3C4/5 and

`IOPortDispatcher.RegisteredHandlers` the pipeline was given (`GeneratorInputs.IoPorts`, a

concrete device type. A program configured differently - a different Sound Blaster base, a
disabled OPL, a replaced handler - keeps its port accesses verbatim.

PIT and OPL included. The attributes declare the protocol shape only: they do not prove that a
match is legal - the DO rows below still decide - and they do not establish semantic equivalence
between the port sequence and the device method. PIT channel programming, the OPL address/data
pairs and the packed VGA word write keep custom matching; the word write reuses the declared
two-write sequence for its target and parameter bindings.

## IrWideComparisons (WC)

Runs late on the lowered pure-relational branches and rewrites decision trees that test a
16-bit pair one half at a time into one comparison of the packed wide value, and inlines a
dead test-writer into its only consumer. Inner blocks may hold only marker statements
(`InstructionStartNode` / `CommentNode`), cannot be the method entry or a structural-successor
anchor, and every incoming edge must come from a matched outer test; removed blocks are proved
unreachable before deletion and all matches are batched against claimed blocks so overlapping
rewrites cannot both fire.

## IrInterruptServiceCalls (IS)

Turns an `int` site on a vector the whole program only ever directed at the built-in stub into a
typed call of the service's declared implementation (`InterruptServiceCallNode`, printed
`(outputs) = ServiceCall(cs, ip, Receiver, () => Receiver.Method(args))`, with no selector and no
input stores). Whether the helper also performs the interpreted `int` + `iret` stack traffic is a
program fact (`InterruptServiceCallNode.WritesFrame`, set from
`HardwareInterruptSetup.ProgramSetCurrentPsp`): a program that executed a program-level DOS 50h or
55h keeps the frame form (the helper pushes FLAGS/CS/IP, clears IF, runs the handler's
`OnInterruptEntry` bookkeeping, invokes the implementation, writes flag results into the stacked
FLAGS through a `stackedFlags` argument and pops the frame like `iret`); every other program's
typed call omits the six-byte frame (no push, no pop, no `stackedFlags` lambda), still clearing IF
for the service duration and restoring the caller IF, and still running the entry bookkeeping on a
stack pointer lowered by six so the saved caller-stack pointer lands where the frame would have
been. The G3 differential gate then excludes exactly the six bytes at `SS:SP-6` each recorded
frameless call site would have overwritten, and nothing else. `HardwareInterruptEffectBuilder.HasOnlyBuiltInTargets` is the whole-vector
predicate the pipeline supplies, over recorded (non-speculative) `int` sites only: every such site
anywhere in the program must have an evaluatable constant vector, and among the sites on this
vector at least one must have observed targets and every observed target must be the installed
stub; a site with no observed target, a custom or chaining target, or a recorded IVT entry (when
the snapshot covers it) pointing elsewhere disqualifies every site of that vector, while a
different constant vector is unrelated and ignored. A speculative `int` - one discovery marked
but never executed - is not a recorded site: it does not qualify or disqualify the recorded
sites of its vector, and its own specialization still requires its own observed targets.
The selector must then be a known constant whose entry declares an `Implementation` whose
signature the declared inputs match - parameters may be a register's CLR type, a safe widening
(`MapUnmapHandlePage`'s `physicalPage` ushort bound to AL), an enum an integer binding casts to
(`SeekFile`'s `SeekOrigin`), or `string` for the single `DS:DX` binding of a `StringArgument`
service, read at run time by `StringDecoder.GetDosString` with the snapshot's literal as a checked
expected value when one was recorded.

The restored families cover the DOS file, memory, drive, time, FCB, PSP and ioctl services, the
BIOS video, clock, keyboard, equipment, memory-size, printer, wait and system services, the EMS
operations and the XMS multiplex service. Cores that returned nullable or domain results were
normalized inside the real core to the tuple the contract outputs declare (preserved outputs like
the input AX or an attribute CX are explicit `previousX` inputs), and services whose inputs the
default input list could not express use an explicit `Inputs` list - `null` means derive from the
contract, `[]` means genuinely no inputs. The exceptions are behavioral, not signature-shaped:
services whose dispatch can terminate the process (the Ctrl-C checking character I/O calls),
the PSP creation services 26h/55h whose parent interrupt frame the termination path consumes,
the unproven subfunctions of 43h/58h (a direct call binds only a constant AL proven supported,
an unsupported operation keeps the dispatcher's post-lookup exception), blocking or nested
services, and any vector with a custom or chained target. A service that passes the whole-vector
predicate but has no bindable implementation keeps `InterruptCall` as `BuiltInDispatch` with the
precise normal-return effects of its contract (contract reads plus the frame's SS/SP/CS/FLAGS/DF,
must-write none, may-write the contract's writes), which preserves segment knowledge through the
call that the fully generic effect would destroy.

One metadata write accompanies every DOS call: `DosInt21Handler` saves the caller
SS:SP into the current PSP (offset 2Eh) on entry for all operations but the PSP get/set
functions, which `TerminateProcess` consumes later. The interpreted `Run` performs it through
`OnInterruptEntry`; the frame form of `ServiceCall` invokes it after pushing the frame, the
frameless form invokes it with SP temporarily lowered by six - in both cases the saved pointer is
the caller SP before the interrupt minus the six frame bytes, through the same code path in both
modes. When the pass replaced at least one statement, the
SSA is rebuilt and `IrConstants` runs again on it, so `IrBranchSimplification` folds across the
direct calls with the contract's narrower effects. The selected cores do not dispatch CPU
interrupts or inspect transient interrupt context. Disk transfers still run the existing
scheduler. Hardware interrupt delivery remains at the existing event checks. The fixture is
`int_service_calls`; each section's comment names the wrong rewrite it catches.

## DOS call comments (ST)

`DosCallComments` records each `int 21h` site whose AH is a known constant right after
`IrConstants`, and after the pipeline resolves a `// DOS ...` comment showing the bytes the service
reads at `DS:DX`: `DOS 09h print "..."`, `DOS 40h write handle n "..."`, or `DOS XXh <name> "..."`
for a service whose contract declares a `StringArgument`. Only bytes `IsUnchanged` proves never
changed during discovery are shown, so the comment cannot print text the call never read. The
fixture is `data_strings`; the generator cases are in `DataCommentTest`. When a `StringArgument`
service is also a bound direct call, the proven string is carried on the call node as
`StringLiteral` and printed as the checked fourth argument of `GetDosString(segment, offset, end,
"literal")`: the decoder throws when the runtime bytes differ from the recorded literal, so a
changed byte can never silently feed a stale string to the core. A changed byte or terminator
keeps the named call but drops the literal to the dynamic two-argument read.

## Register locals (RL)

A register web - versions joined through phis and through calls that preserve the
register - prints as a C# local with a generic width-prefixed name (`word1`), numbered per
prefix by the address of the web's first definition, webs that shared one register name sharing
one local, with a write-back (`AX = word1;`) before the first use the local cannot serve. The plan is

## StackRuns (SV)

on the final body): the method's entry pushes print as `Stack.Save(...)`, an exit run of register
pops as `(...) = Stack.Restore<n>()` (a dead pop inside the run prints as a `_` discard slot),
and dead pops (DW-6) as `Stack.Release(n)`. The helpers run

SP steps are unchanged. The rewrite is emission-only and runs after the last body rewrite, so no
analysis sees it.

## Typed signatures (TS)

parameters from the entry's inputs, outputs and return type from its outputs, one 16-bit return
distance and popped byte count. A typed method's body starts by assigning each parameter to its
register, so a wrong signature shows up as wrong behavior for every caller. `TypedCallOf` then
decides which call sites may print the typed form; a site that keeps the untyped helper is
always safe, so the site rules only gate the readable form.

## Stack arguments (SA)

## Trap debt

Rows whose evidence cannot produce a machine oracle today, so their conditions are pinned by
unit tests alone:

- **PT-4, PT-6** - no current fixture produces the shape (a `R = t` copy with a second reader;
  lifted temps of mixed types).
- **PT-1 / PT-3 token halves** - no instruction lowering builds a token-reading temp with
  another statement between it and its reader.
- **SF-2, SF-3, SF-4, SF-5, SF-6** - a dead/forwardable store is an emission-time rewrite with
  no runtime signature distinguishable from the correct one; the scenarios never leave a byte
  in a result region that depends on the removed store.
- **AL-5** - the alias walk's conservative refusal on an unpinned segment is covered by unit
  tests; no fixture drives it.
- **HI-2, HI-3** - a mutation there only widens `Writes` or `Uses`, which is conservative: no
  machine oracle can fail (HI-2 states it in its evidence column).
- **HI-4, mouse user subroutine half** - no fixture can deliver IRQ12, so the effect addition
  of the far-called subroutine's registers is pinned by a unit test.
- **SG-2, SG-3, SG-4** - the speculative-guard merge barriers (interrupt delivery, faults, port
  writes, full memory boundaries, unproven writes) are pinned by unit tests; no fixture runs a
  merged guard across one.
- **TS-3c, TS-6a, TS-6b, TS-8b, TS-13** - golden-only rows: dropping them turns untyped methods or
  call sites typed or only changes printed names, which changes the generated text
  (`Entry(..._Asm)` renames, a typed call at a multi-target site, a `MethodCallNode` exit getting
  a signature, a register name in a branch condition) but no fixture drives the wrong output into
  observable behavior.
- **TS-6d, TS-12** - mutations recorded as not observable: the BP copy only feeds `mov sp, bp`
  restores and BP-relative slot kills no fixture section prints through, and removing a machine
  input from a call's reads cannot kill its feeding write (dead-write elimination works through
  operand substitution; a machine input has no operand). `cc_stack_offset_joins` S5/S6 are the
  guards, and TS-12's generation-time `inputs & ~Reads & ~operandCovered` check throws on a real
  miss.
- **TS-7** - unit test only (`ReturnSlotWrite_IsNotTyped`): an oracle would need a callee whose
  return-slot write lands on an address discovery never observed from that call site, and when
  discovery sees the redirect the site keeps the `...ReturnedElsewhere` helpers instead.
- **TS-3b, TS-8a, FR-1, FR-3b, FR-5, FR-6** - unit test only: no fixture produces the shape (mixed
  return pop counts, an unobserved continuation at a typed-call-eligible site, a non-SS access
  through an SP copy, disagreeing copy operands, a pointer node shared with a non-frame
  occurrence, a `mov bp,sp` at another delta).
- **TS-2, FR-3a, FR-4b** - unreachable, no test: a method passing TS-3 always has a returning
  entry; an `HasEntryOperand` phi's copy operands cannot resolve through the entry event check's
  `Unknown` incoming offset; a check/guard partial definition's previous version is always an
  entry version or a loop-head phi that is never a copy.
