# Legality catalogue - IR data-flow rewrites

Every condition a rewrite checks before it applies, what goes wrong without it, and what proves
it is load-bearing. "Trapped" means a mutation that drops the condition fails an oracle (or
fails to compile the generated code, or throws). Rows that cannot be proven by an oracle carry
one of:

- `redundant (covered by <id>)` - another condition refuses the same rewrites first;
- `unreachable` - no input in the fixtures reaches the code path;
- `readability` - an output-size or shape gate that does not change behavior;
- `not trappable` - dropping the condition is observably safe;
- `unit test only` - covered by a unit test because no fixture can produce the shape.

A row id is a short name for one condition (a prefix for the rewrite family and a number); the
fixture section comments use the same ids. The `code` column names the IR pass member that
implements the row now. Rows whose old code was deleted and whose condition is now implied by
the IR model say so.

`dataflow_legality_traps` is the fixture added for the conditions no earlier fixture covered;
its section comments name the row ids. Mutations ran serially; each was reverted after its
run.

## Memory alias analysis (AL)

`IsKnownRam` keeps rewrites away from device mappings. `IrExpressionPropagation` (EP-5) and
`IrStoreForwarding` (SF) are its users.

## Segment values (SV)

`IrSegmentValues` resolves, for the register version a statement reads, a `SegmentValue`:
`Known(constant)`, `Symbolic(root version)` or `Unknown`. Two registers hold the same value
(`SameValue`) when both are `Known` with one constant or both `Symbolic` with one root. A
`Symbolic` root is sound because an SSA version names one static definition: two registers
holding copies of root `V` at one statement hold the same dynamic value - if `V`'s definition
ran again between the two copies, the path crosses a loop header where the later-read register
is live and gets a phi, and SV-4 then needs every phi operand to have root `V`, which an operand
from outside the loop cannot. The same holds for SV-3 because `Complete` requires the definition
on every path. The shared constant-resolution helper is `IrSegmentValueResolver`, which
`IrMemoryAliasAnalysis` uses for its `SegmentValue` fields.

## IrDeviceOperations (DO)

Recognizes a constant-port access sequence inside one basic block as a device protocol and
replaces it by one call on the device (`Cmos.ReadRegister` / `WriteRegister` for the 0x70/0x71
pair, `Pit.ProgramChannel` for a low/high control word plus its two channel data writes,
`Vga.SetPaletteEntry` for the DAC write index plus its three data writes,
`Vga.WriteSequencerRegister` / `Vga.WriteGraphicsControllerRegister` for the 0x3C4/5 and
0x3CE/F pairs, `Opl.WriteRegister` for the OPL address/data pairs). Runs after the additive
constant fold; when it combined at least one sequence the pipeline rebuilds the SSA
(`ssa build device operations`) and the webs before `DoublePrecision`.

Precondition: the pass only treats an address as reaching a device when the snapshot of
`IOPortDispatcher.RegisteredHandlers` the pipeline was given (`GeneratorInputs.IoPorts`, a
port-to-handler-type map captured at generation time) records the port's handler as the exact
concrete device type. A program configured differently - a different Sound Blaster base, a
disabled OPL, a replaced handler - keeps its port accesses verbatim.

## IrDoublePrecision (DP)

Recognizes `add`/`adc`, `sub`/`sbb`, `neg`/`adc`/`neg`, `shl`/`rcl` and `shr`/`rcr` on a register

it rewrote at least one pair the pipeline rebuilds

## Trap debt

Rows whose evidence cannot produce a machine oracle today, so their conditions are pinned by
unit tests alone:

- **PT-4, PT-6** - no current fixture produces the shape (a `R = t` copy with a second reader;
  lifted temps of mixed types).
- **PT-1 / PT-3 token halves** - no instruction lowering builds a token-reading temp with
  another statement between it and its reader.
- **SF-2, SF-3, SF-4, SF-5, SF-6** - a dead/forwardable store is an emission-time rewrite with
  no runtime signature distinguishable from the correct one; the scenarios never leave a byte
  in a result region that depends on the removed store.
- **AL-5** - the alias walk's conservative refusal on an unpinned segment is covered by unit
  tests; no fixture drives it.
- **HI-2, HI-3** - a mutation there only widens `Writes` or `Uses`, which is conservative: no
  machine oracle can fail (HI-2 states it in its evidence column).
- **HI-4, mouse user subroutine half** - no fixture can deliver IRQ12, so the effect addition
  of the far-called subroutine's registers is pinned by a unit test.
- **SG-2, SG-3, SG-4** - the speculative-guard merge barriers (interrupt delivery, faults, port
  writes, full memory boundaries, unproven writes) are pinned by unit tests; no fixture runs a
  merged guard across one.
- **TS-3c, TS-6a, TS-6b, TS-8b** - golden-only rows: dropping them turns untyped methods or call
  sites typed, which changes the generated text (`Entry(..._Asm)` renames, a typed call at a
  multi-target site, a `MethodCallNode` exit getting a signature) but no fixture drives the
  wrong signature into observable behavior.
- **TS-7** - unit test only (`ReturnSlotWrite_IsNotTyped`): an oracle would need a callee whose
  return-slot write lands on an address discovery never observed from that call site, and when
  discovery sees the redirect the site keeps the `...ReturnedElsewhere` helpers instead.
- **TS-3b, TS-8a, FR-1, FR-3b, FR-5, FR-6** - unit test only: no fixture produces the shape (mixed
  return pop counts, an unobserved continuation at a typed-call-eligible site, a non-SS access
  through an SP copy, disagreeing copy operands, a pointer node shared with a non-frame
  occurrence, a `mov bp,sp` at another delta).
- **TS-2, FR-3a, FR-4b** - unreachable, no test: a method passing TS-3 always has a returning
  entry; an `HasEntryOperand` phi's copy operands cannot resolve through the entry event check's
  `Unknown` incoming offset; a check/guard partial definition's previous version is always an
  entry version or a loop-head phi that is never a copy.
